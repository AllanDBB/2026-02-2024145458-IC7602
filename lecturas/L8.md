Pregunta 1: Explique el funcionamiento de ICMP. ICMP (Internet Control
Message Protocol, RFC 792) es el protocolo que usan los hosts y routers para
reportar errores y intercambiar información de control sobre la entrega de
datagramas IP. Aunque se considera parte de la capa de red, sus mensajes no
viajan directamente sobre la capa de enlace, sino encapsulados dentro de un
datagrama IP (campo Protocol = 1 en IPv4). IP por sí solo es un servicio de
"mejor esfuerzo" que no avisa cuando algo falla; ICMP llena ese vacío
permitiendo que, por ejemplo, un router que descarta un paquete le notifique
al origen el motivo. Es importante notar que ICMP no hace que IP sea
confiable: no retransmite nada ni garantiza que sus propios mensajes
lleguen, solo informa.

Todo mensaje ICMP tiene un encabezado común:

- Type (8 bits): la clase de mensaje (por ejemplo, 8 = Echo Request,
  0 = Echo Reply, 3 = Destination Unreachable, 11 = Time Exceeded).
- Code (8 bits): precisa la causa dentro de ese tipo (por ejemplo, para el
  tipo 3: 0 = red inalcanzable, 1 = host inalcanzable, 3 = puerto
  inalcanzable, 4 = se requiere fragmentar pero el bit DF está activo).
- Checksum (16 bits): verifica la integridad del mensaje ICMP completo.
- Resto del encabezado (32 bits): depende del tipo; por ejemplo, en un Echo
  lleva un identificador y un número de secuencia, y en un "Fragmentation
  Needed" lleva el MTU del siguiente salto.

Los mensajes se dividen en dos grandes grupos:

- Mensajes de error: los genera un router o el host destino cuando no puede
  procesar un datagrama. Los principales son Destination Unreachable
  (tipo 3), Time Exceeded (tipo 11, cuando el TTL llega a 0 o no se logra
  reensamblar los fragmentos a tiempo), Parameter Problem (tipo 12, cuando
  el encabezado IP es inválido) y Redirect (tipo 5, cuando un router le
  indica a un host que existe una mejor ruta en la misma red). Como datos,
  incluyen el encabezado IP del datagrama original más los primeros 8 bytes
  de su contenido, lo que basta para que el origen identifique el protocolo
  y los puertos (TCP/UDP) involucrados y le entregue el error a la
  aplicación correcta.
- Mensajes de consulta (informativos): funcionan como pares solicitud /
  respuesta, siendo el más conocido Echo Request / Echo Reply (tipos 8 y 0).
  Otros como Timestamp o Address Mask existieron en el diseño original pero
  hoy son obsoletos.

Para evitar que ICMP empeore una situación de congestión o genere
tormentas de mensajes, existen reglas sobre cuándo NO se debe generar un
error: nunca en respuesta a otro mensaje de error ICMP, ni por datagramas
dirigidos a direcciones broadcast o multicast, ni por fragmentos que no sean
el primero, ni por datagramas cuyo origen no identifique un único host.
Además, los routers suelen limitar la tasa (rate limiting) de mensajes ICMP
que generan. En IPv6 existe ICMPv6 (RFC 4443, Next Header = 58), que
mantiene la misma idea pero asume más responsabilidades: agrega el mensaje
Packet Too Big (en IPv6 los routers no fragmentan) e integra Neighbor
Discovery (que reemplaza a ARP) y Multicast Listener Discovery (que
reemplaza a IGMP), por lo que en IPv6 bloquear ICMP rompe la red.

Pregunta 2: Comente las aplicaciones de este protocolo en las
comunicaciones.

- Ping (verificación de alcanzabilidad): envía Echo Requests y espera los
  Echo Replies, lo que permite comprobar si un host está activo y medir el
  tiempo de ida y vuelta (RTT), la variación de latencia y el porcentaje de
  pérdida de paquetes. Es la primera herramienta de diagnóstico que se usa
  ante un problema de conectividad.
- Traceroute (descubrimiento de la ruta): aprovecha el mensaje Time
  Exceeded. Envía paquetes con TTL = 1, 2, 3, ..., de modo que cada router
  del camino, al decrementar el TTL a 0, descarta el paquete y responde con
  un ICMP tipo 11 que revela su dirección. Cuando el paquete finalmente
  alcanza el destino, este responde con Port Unreachable (si se usaron
  sondas UDP a puertos altos, como en Unix) o con Echo Reply (si se usaron
  sondas ICMP, como el `tracert` de Windows), lo que indica que se llegó al
  final. Así se puede ubicar en qué salto se pierde o se demora el tráfico.
- Path MTU Discovery: el origen envía paquetes con el bit DF (Don't
  Fragment) activo; si un enlace intermedio tiene un MTU menor, el router
  responde con Destination Unreachable / Fragmentation Needed (o Packet Too
  Big en IPv6) indicando el MTU permitido, y el origen ajusta el tamaño de
  sus paquetes. Esto evita la fragmentación, que es costosa. Cuando un
  firewall bloquea estos mensajes se produce un "agujero negro" de PMTUD:
  las conexiones se establecen pero se cuelgan al enviar paquetes grandes.
- Notificación de errores a las aplicaciones: gracias a Destination
  Unreachable, una aplicación (o la pila TCP/UDP del sistema) puede saber
  rápidamente que un host, red o puerto no está disponible, en lugar de
  esperar a que expire un temporizador. Por ejemplo, un cliente UDP recibe
  "connection refused" cuando llega un Port Unreachable.
- Optimización de rutas: los mensajes Redirect permiten que un router
  le indique a un host de su misma red que use otro gateway más directo
  para cierto destino, corrigiendo tablas de enrutamiento mal configuradas.
- Funcionamiento básico de IPv6: con ICMPv6 se realizan la resolución de
  direcciones (Neighbor Solicitation/Advertisement), el descubrimiento de
  routers y la autoconfiguración de direcciones (Router
  Solicitation/Advertisement, SLAAC) y la detección de direcciones
  duplicadas, por lo que ahí ICMP deja de ser solo de diagnóstico y se
  vuelve indispensable.
- Monitoreo y gestión de redes: herramientas como Nagios, Zabbix o
  PRTG usan pings periódicos para supervisar la disponibilidad de equipos y
  enlaces, y comandos como `mtr` combinan ping y traceroute para medir de
  forma continua la calidad de cada salto.
- Seguridad (uso ofensivo y defensivo): por su utilidad, ICMP también se
  usa en ataques: barridos de ping (ping sweeps) para descubrir hosts
  activos, fingerprinting de sistemas operativos según cómo responden,
  inundaciones de Echo (ICMP flood), el ataque Smurf (pings a una dirección
  broadcast con el origen falsificado de la víctima), el histórico "Ping of
  Death" (paquetes malformados de tamaño excesivo) y túneles ICMP que
  esconden datos dentro de los Echo para evadir firewalls. Por eso los
  administradores filtran o limitan ICMP, pero bloquearlo por completo es
  un error, ya que rompe PMTUD y el diagnóstico (y en IPv6 rompe la red);
  la recomendación (RFC 4890) es permitir selectivamente los tipos
  necesarios, como Fragmentation Needed / Packet Too Big, Time Exceeded y
  los mensajes de Neighbor Discovery.
