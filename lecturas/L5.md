Pregunta 1: ¿Cómo funciona el Port-Based Authentication? Es un mecanismo de
control de acceso a la red (definido en el estándar IEEE 802.1X) que opera a
nivel del puerto de un switch o de un access point inalámbrico, antes de que
el dispositivo conectado pueda enviar tráfico normal. Cuando un dispositivo
se conecta, el puerto queda en estado "no autorizado" (unauthorized): solo se
permite tráfico de autenticación (EAPOL/EAP), y se bloquea todo lo demás
(DHCP, ARP, tráfico IP, etc.), por lo que el dispositivo ni siquiera puede
obtener una dirección IP todavía. El switch encapsula los mensajes EAP del
cliente y los reenvía a un servidor de autenticación (normalmente RADIUS),
que valida las credenciales. Si la autenticación es exitosa, el servidor le
indica al switch que autorice el puerto, y a partir de ese momento el
dispositivo puede enviar y recibir tráfico normal (en algunos casos incluso
se le asigna una VLAN específica según el resultado). Si falla, el puerto
permanece bloqueado o se reubica en una VLAN restringida (por ejemplo, una
VLAN de invitados con acceso limitado).

Pregunta 2: Componentes principales de 802.1X.

- Supplicant: el dispositivo cliente que solicita acceso a la red (laptop,
  teléfono, impresora, etc.) y que corre el software necesario para hablar
  el protocolo EAP.
- Authenticator: el switch o access point que controla físicamente el
  acceso al puerto. No decide si el usuario es válido; solo actúa como
  intermediario, encapsulando/desencapsulando los mensajes entre el
  supplicant (EAPOL) y el servidor de autenticación (RADIUS).
- Authentication Server: normalmente un servidor RADIUS, a menudo
  integrado con un directorio de usuarios (Active Directory/LDAP), que
  valida las credenciales y decide si se autoriza o rechaza el acceso, y
  puede indicar políticas adicionales (como la VLAN a asignar).
- EAP (Extensible Authentication Protocol): protocolo marco que transporta
  distintos métodos de autenticación (EAP-TLS, PEAP, EAP-FAST, etc.) entre
  el supplicant y el servidor.
- EAPOL (EAP over LAN): la forma en que se encapsula EAP a nivel de capa 2
  entre el supplicant y el authenticator, ya que en ese punto el
  dispositivo todavía no tiene conectividad IP.
- Puerto controlado / no controlado: conceptualmente el puerto del
  authenticator se divide en dos canales lógicos: uno no controlado, que
  solo deja pasar tráfico EAPOL, y otro controlado, que se habilita para
  tráfico normal una vez completada la autenticación.

Pregunta 3: ¿Por qué considera que este tipo de autenticación es relevante?
Porque mueve el control de acceso a la capa más baja posible (capa 2), antes
de que un dispositivo no autorizado pueda siquiera obtener una IP o generar
tráfico dentro de la red, lo cual reduce mucho la superficie de ataque frente
a alguien que simplemente conecta un cable a un puerto libre o se asocia a
una red inalámbrica. Es la base de los sistemas de Network Access Control
(NAC) en entornos empresariales, porque permite asegurar que solo
dispositivos y usuarios autenticados (empleados, equipos gestionados por la
organización) entren a la red cableada o inalámbrica, y además permite
aplicar políticas dinámicas, como asignar automáticamente VLANs distintas
según el rol del usuario (por ejemplo, VLAN corporativa vs. VLAN de
invitados). Al integrarse con un directorio centralizado (RADIUS/AD), evita
depender de configuraciones manuales por dispositivo (como MAC filtering) y
se vuelve mucho más escalable y auditable. Por último, es una pieza
fundamental en arquitecturas Zero Trust, donde la conectividad a la red no
implica confianza automática, sino que cada dispositivo debe demostrar su
identidad antes de comunicarse con cualquier recurso.
